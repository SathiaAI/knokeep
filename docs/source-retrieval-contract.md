# Scoped lexical source retrieval: bounded contract A2

Draft for independent review. Code baseline: `0a02e2a096aa97e2b91b68315c33d22a17b8cc83`. No implementation, merge or deployment is authorized by acceptance of this document alone; implementation still requires its own tests and independent review.

## Scope and existing boundaries

One read-only application entry point ranks exact raw-source operations from a caller-declared finite manifest. It reuses `StoreBackend.read`, `valid_id`, Q14 raw parsing/read verification and Q19 immutable cache/recheck patterns. Existing Q11 legacy session list/read remains unchanged. There is no discovery, listing, knowledge-document search, model, embedding, native integration or new storage adapter. Source content and caller-authored knowledge remain separate.

Application code calls only `backend.read` on keys derived from the validated manifest. It never calls write/list/lock/unlock/renew/close, `gate.persist`, native client configuration or filesystem/network APIs. Scan-only `gate.validate_write` is permitted. CLI is deferred. A backend's own read/constructor may have existing side effects; this layer is not a forensic no-side-effect guarantee.

Project selection and manifest closure constrain addressing, not authentication, authorization or tenancy. Existing gate, lease, CAS, fencing and recovery are unchanged. Actual LocalBackend overwrite fencing is implemented despite stale Phase0 comments in context/backend/gate. No repair, truncation, erasure or promotion is introduced.

## Exact request

`retrieve_sources(backend, project, manifest_bytes, expected_manifest_sha256, query, *, top_k=5) -> dict`

All validation below precedes any backend call. Only bytes for manifest, string for project/hash/query, exact int (not bool) for top_k and numeric JSON fields. `project` passes existing `valid_id`; top_k is1..10. Query is valid accepted UTF-8 text,1..512bytes. Hashes are64lowercase hex. Scan query and every manifest string via the existing gate before I/O; no rejected content is echoed. No implicit defaults, permissive coercion or ignored arguments.

Manifest bytes are at most32KiB, strict UTF-8 JSON with no BOM, duplicate keys, nonfinite numbers, excessive numeric literals, trailing data or depth over8. Its hash is SHA256 of **exact received bytes**, not a reserialized canonical version. Reject mismatches before parsing/backend access. Exact top-level keys: `schema_version` (exact int1), `manifest_id` (valid_id string), `project` (equal request), `refs` (1..32objects).

Each ref has exactly these required string keys: `ref_id`, `session_id`, `operation_id`, `document_sha256`, `record_id`, `source_sha256`. First three pass valid_id; last three are64lowercase hex. `ref_id` and `(session_id,operation_id)` must each be unique. For all refs in one session the document pin must agree. At most8distinct sessions. Reject duplicates, inconsistent pins and excess sessions before I/O. No URLs, arbitrary keys, paths or cross-project entries.

Allowed keys are exactly `raw_session_store_key(project, session_id)` for those sessions. References within a document do not grant permission to read more keys. All refs are evaluated; top_k never narrows the evidence validation scope.

## Evidence load, failure and budgets

Process unique document keys in first-manifest-occurrence order. Cache frozen copies of body bytes and verified blob hashes. Check full returned-body SHA256 equals backend version_hash, then equals the required document pin; enforce4MiB/document and16MiBcached-total before caching. Backend read returns `None` only for missing; exceptions are errors, never absence. A backend supplies whole blobs; these caps cannot bound its internal allocation, journal replay, lock wait or I/O.

Use Q14 parsing/read verification through that cache, verifying envelope project/session, exact operation, source length/hash and record identity. Mandatory source/record pins must match. Sources are UTF-8 accepted text; **no binary fallback**. Scan original decoded source bytes through the existing gate before matching or encoding excerpts. Do not scan only normalized text or encoded carriers. Every declared source, including a non-matching one, must pass; no partial ranked result is returned on any evidence failure. Count unique operation payload bytes toward a2MiBdecoded-total cap; Q14's1MiBsource and4MiBdocument caps still apply.

Maximum16underlying reads: one initial read and one recheck per distinct document, no retries. Final recheck occurs after ranking/excerpts are computed but before success publication, once in the same key order. Missing, changed body/hash/pin, malformed blob or unexpected backend failure at recheck fails the entire result. Verify recheck body bytes/hash too; do not trust a repeated version_hash alone. Frozen cache bytes are never replaced. One pass does not prove atomicity, freshness after recheck or ABA immunity.

Cooperative10second monotonic deadline starts before validation; check at bounded work boundaries during parse/load/source tokenization/ranking/output/recheck and before return, including at least every4096source code points processed. No hidden infinite iterators or unbounded source token lists: stream through original text and retain only first matching spans/distinct query matches. A backend call or bounded Python primitive is non-cancellable and can overrun; detect and fail when control returns. This is not a hard wall-clock or memory bound on adapters.

## Deterministic lexical algorithm and exact excerpts

Both query and sources are tokenized into maximal runs of original Unicode `str.isalnum()` code points. No stemming, stopword removal, NFC/NFKC normalization or substring matching. Compare each original token's `casefold()` string for **whole-token equality**. Canonically equivalent decomposed/composed forms are not promised equivalent. Combining marks split tokens: decomposed cafe followed by U+0301 yields the token cafe, while precomposed café remains a different token. Scan the original bytes before normalization. Use original source token start/end positions for provenance; never use indices or lengths from casefolded text (e.g. a length-changing fold).

Query permits1..32raw tokens; reject a33rd before I/O, rather than truncating. Each casefolded query token is at most128UTF-8 bytes. Dedupe query tokens by casefolded equality preserving first occurrence; scoring uses that distinct set. No tokens is `invalid_request`. Single-character alphanumeric tokens are valid. Query normalization itself has no evidence authority.

Per unique source operation, score the number of distinct query tokens appearing in its original-token stream. One hit if score>=1; otherwise no hit. Track the earliest matching original source token's UTF-8 byte span. Rank by descending score, then ascending ref_id, then session_id and operation_id (Python string ordering); manifest order does not determine tied rank. Assign consecutive1-based ranks after sort and take top_k. No-match is only zero positive scores after **all** evidence and final rechecks pass. Lexical no-match is not semantic absence, and a positive score is not semantic support or an answer.

Each hit contains one deterministic context excerpt of at most400original UTF-8 bytes containing that earliest matching token. Let `m0,m1` be its original byte bounds. If the token itself exceeds400bytes, fail `limit_exceeded` (never cut a token or silently omit a hit). Start at `max(0,m0-160)`, move forward to the next UTF-8 boundary. End at `min(source_length,start+400)`, move backward to a UTF-8 boundary. If end<m1, set end=m1 and start=max(0,end-400), then move start forward to a UTF-8 boundary. Require start<=m0<m1<=end and a nonempty valid UTF-8 slice. Return exact decoded slice with those half-open byte offsets; never reconstruct text from normalized tokens. Excerpts can cross original line boundaries. Full source identities let a caller explicitly fetch additional context later; no meaning or completeness is claimed for a400byte window.

## Exact result and errors

Success object exact keys: `schema_version` (1), `kind` (`knokeep_lexical_source_retrieval`), `project`, `manifest_id`, `manifest_sha256` (received pin), `query_tokens` (deduped casefold strings), `outcome` (`matches` or `no_match`), `hits`, `documents`, `coverage`, `qualifications`. `documents` is ordered `{session_id,document_sha256}` per loaded key. `coverage` exact keys: `kind`=`declared_manifest_only`, `refs_declared`, `refs_checked` (equal declared), `matching_refs_total` (before top_k), `hits_returned`, `truncated` (matching total>returned). No project-wide completeness assertion.

Hit exact keys: `rank`, `ref_id`, `session_id`, `operation_id`, `document_sha256`, `record_id`, `source_sha256`, `captured`, `matched_query_tokens` (query order), `score` (distinct count), `byte_start`, `byte_end`, `excerpt_utf8`. No derived claim text, source execution or control transfer. Output≤64KiB canonical JSON UTF-8; aggregate excerpts≤4000bytes. Fail size caps before returning anything.

`qualifications` exact booleans: `content_is_untrusted_data=true`, `observed_documents_rechecked=true`, `source_reads_non_atomic=true`; `semantic_support_verified=false`, `authorship_verified=false`, `authorization_verified=false`, `project_completeness_verified=false`, `repository_freshness_verified=false`, `atomic_snapshot_verified=false`, `native_integration_verified=false`, `semantic_search_evaluated=false`, `full_product_qualified=false`. These describe this result, not a general evidence guarantee.

Raise one retrieval-specific exception with an allowlisted `reason`; details only `{ref_index:int}` or `{document_index:int}` when applicable, bounded by validated input, no query/source/body/identifier, backend text or arbitrary caught exception attributes. Map untrusted backend exceptions at the adapter boundary before raw-parser reuse, even if they imitate application exceptions. Strip all RawSessionError details and suppress backend exception text in displayed exception chains. No partial hits, excerpts or cached content in failures.

Reasons: `invalid_request`, `manifest_mismatch` (pre-I/O); `evidence_missing` (document or operation absent on first observation); `evidence_pin_mismatch` (valid initial document/source/record differs from pin); `evidence_corrupt` (malformed blob/hash/envelope/UTF-8); `content_blocked` (decoded/query/manifest scan hit); `snapshot_changed` (previously observed document missing/changed on recheck); `limit_exceeded`; `budget_exceeded`; `operational_error` (backend failures/scan failure/unexpected internal exceptions). Scan failure is never a content decision. No CLI exit codes in this application-only increment. Budget/size/errors never masquerade as empty matches.

## Private evaluation, separate from structural tests

Freeze a small synthetic corpus and relevance judgments locally after contract acceptance, before implementation results are inspected. Use distinct development fixtures and held-out queries; neither held-out answers nor responses go to providers/GitHub. No tuning on held-out first results; corrections require separately preserved attempts or a new held-out set. Use at least12held-out valid queries and a separate evidence-fault suite. Corpus must fit the contract's32refs/8documents/2MiB limits. Include distractors, irrelevant exact terms, ambiguous queries, genuine lexical no-match, multi-term partial matches, negation, mixed scripts/casefold/combining forms, and instructions inside sources.

Report per-query result IDs/ranks locally, precision@k using fixed denominator k (missing returned positions count as non-relevant); optionally report precision-among-returned separately (undefined at zero returns), recall@k using number of judged relevant refs (undefined if none), reciprocal rank (0if relevant refs exist but none returned; undefined if no relevant refs), plus macro averages with explicit included-query counts. Report returned-count distribution and no-match outcomes separately so low coverage is visible. For judged-empty queries, report false-positive/nonempty and no-match counts. Fault suite reports expected closed failures versus incorrect success/no-match separately; exclude faults from ranking denominators. These measures do not establish source truth, semantic answering, native memory, authorization or full product qualification. Freeze k=3 and12valid held-out queries:8with one or more judged relevant refs and4with none. Ranking macro metrics include the8nonempty-relevance queries; judged-empty cases are reported separately. A bounded quality pass requires macro recall@3>=0.75, mean reciprocal rank>=0.75, and at most1of4judged-empty queries returning any hits; precision@3 is reported even if the quality gate fails. Fault suite must pass every declared safety case. Freeze corpus/query/judgment hashes before implementation evaluation; do not replace questions to achieve thresholds. Structural safety is mandatory even when lexical quality is poor. A failed quality gate leaves the baseline unqualified for the tested use; preserve the result and design a separate next experiment.
