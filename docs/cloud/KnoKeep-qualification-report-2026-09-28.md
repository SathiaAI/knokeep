## Failures that change the plan

1. **Correct bytes can contain a wrong decision.** Cursor's brief rejected a proposal to include all below-threshold items; its saved log instead said to reject all below-threshold items. The store and receipts matched. Fix: retain accepted decisions, rejected proposals, source references and unresolved questions distinctly; test their meaning as well as their hashes. A summary cannot be sold as an exact conversation record.
2. **Uncertainty disappeared during successful work.** Devin noticed the contradiction but its updated current record omitted the unresolved interpretation. Fix: block the affected decision or retain a clearly provisional result; carry the open question into the next current record until authorized resolution. A separate report is insufficient.
3. **A retry could duplicate a durable append.** Killing a real writer after journal fsync but before its response then repeating legacy session_append produced another entry. Fix prepared: stable operation IDs, same-ID/different-payload rejection, and honest current-version receipts. Callers must actually supply the ID; legacy no-ID calls still repeat.
4. **One milestone is several independently durable writes.** A reconstructed accepted boundary contains new architecture and an old conflicting constraint. No data corruption is needed. Fix requires a versioned, complete-checkpoint contract; [the proposal](KnoKeep-milestone-completion-proposal-2026-09-28.md) is not implementation. A zero conflict count means no parked storage conflicts, not semantically consistent prose.
5. **Resume hid the end of a decision.** Active/Next were silently cut at 400 characters. The candidate now preserves complete fields and explicitly warns about shortened previews.
6. **Windows had two failure mechanisms.** Separating preparatory lease setup fixed one test issue; CI then exposed a production fence-file sharing violation. The repair now uses bounded metadata replacement and bounded read-side handling. The real held-open file test and all cross-platform candidate checks passed. Independent removal of the fix caused six of seven new tests to fail; the original CI trigger itself is not proven.
7. **Publication is part of correctness.** Cloud commits remained private to a sandbox, ignored metadata was omitted, line endings changed, and providers appended private task links despite instructions. Exports now have verified blob/byte manifests and a coordinator review. Earlier public metadata copies may persist; removing a current description does not erase caches.
8. **A prompt is not isolation.** Hermes searched source/oracle parents despite a prohibition. Future comparative tests need enforced input boundaries, not just careful wording.
9. **A durable write could lose its place to a stale successor.** With the parent backend still open, a child fsynced a new checkpoint head into the journal and exited before publishing it. The parent then accepted a competing write against the old published head. A fresh backend would have replayed the journal first. The real process-kill regression failed on the candidate; [issue55](https://github.com/SathiaAI/knokeep/issues/55) tracks recovery before write decisions. This blocks release despite the earlier green suite. The original failure remains retained. PR57 fixes this overwrite, confirmed by the independent no-fresh-reader reproduction, but the availability limitation below remains.

10. **Health could say healthy while storage was unusable.** A malformed journal length caused OverflowError during restart and writes, yet the health command reported healthy because it discarded the exception. The command also replayed storage despite being described as read-only. [Issue59](https://github.com/SathiaAI/knokeep/issues/59) now has an actual Cursor implementation under Codex review. The first pass failed five independent cases; a second pass fixed those but failed five additional malformed-telemetry/link cases. The final [PR62](https://github.com/SathiaAI/knokeep/pull/62) passed 11 independent probes, 49 health checks, 10 evaluation checks on Windows and all 8 exact-head CI checks. Earlier failures remain versioned. Inspection assumes a cooperative offline snapshot; it is not a filesystem security sandbox or linearizable concurrent read.
11. **Failing safely is not recovering service.** PR57 correctly refuses writes behind an unreadable journal tail. An interrupted final append therefore blocks every subsequent write, even after restart. Independent Claude reproduced this. No repair tool exists; automatic truncation could discard later durable records in older damaged stores. The release gate needs a recovery design that preserves original bytes and states what it can establish.
